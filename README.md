# The International Chasquis — Technical Showcase

**The International Chasquis** is a real-world web application under active development, focused on financial orientation and cross-border transfer workflows between Europe and Peru.

> **Public Showcase Notice:** This repository documents the technical evolution of the project for professional and portfolio purposes. The production codebase, business logic, credentials, sensitive configuration, customer information, and internal operational details remain private.

---

## 🚀 Project Purpose

This project combines two objectives:

1. Build a functional web platform around a real business use case.
2. Develop and demonstrate practical software engineering skills through a continuously evolving production project.

Rather than presenting an isolated tutorial project, this showcase documents the evolution of a system involving authentication, data persistence, access control, private document handling, operational workflows, deployment, security decisions, and continuous iteration.

---

## 🧠 Spec-Driven Development (SDD) & AI-Assisted Engineering

The project is developed using a structured **Spec-Driven Development (SDD)** workflow combined with **AI-assisted software development**.

AI is used as an engineering collaborator throughout the development process — not as a replacement for understanding, validation, or human decision-making.

The workflow includes:

- **Specification before implementation:** requirements, user flows, expected behavior, data structures, and constraints are defined before major implementation work.
- **AI-assisted problem solving:** AI is used to analyze development problems, explore possible solutions, assist with debugging, and evaluate implementation alternatives.
- **Controlled implementation:** features are developed incrementally from previously defined requirements rather than accepting large amounts of unverified generated code.
- **Human-directed decisions:** product behavior, architecture decisions, security requirements, validation, and final acceptance remain human-directed.
- **Testing and verification:** AI-assisted solutions are checked against expected system behavior before being accepted.
- **Security review:** credentials, private data, storage decisions, access control, and repository exposure are reviewed throughout development.
- **Session continuity:** important development sessions conclude with documented progress, decisions, technical state, pending work, risks, and the next implementation point.

This workflow allows me to develop practical experience collaborating effectively with modern AI tools while maintaining a structured, traceable, and security-conscious engineering process.

## 🔐 Security-Oriented Development

Security is treated as a continuous development requirement rather than a final deployment task.

Current practices include:

- Secrets kept outside the repository
- Environment variables for sensitive configuration
- `.env` excluded from version control
- Private storage for identity documents
- Separation between the public portfolio and private production codebase
- Access controls restricting customers to their own information
- Review of changes before commits and deployment
- No customer documents, credentials, API keys, database passwords, or sensitive operational data are published in this showcase
